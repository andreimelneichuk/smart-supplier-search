# Поиск поставщиков продуктов питания

Сервис для закупщика: найти производителей нужного продукта рядом с нужным городом, собрать по ним ключевую информацию, сравнить и решить, кому писать первым.

Тестовое задание на позицию **AI Generalist / AI Automation Specialist** (часть 2).

**Демо:** https://smart-supplier-search-6o5krctpkuhqe28gnyqrti.streamlit.app/ · **Репозиторий:** https://github.com/andreimelneichuk/smart-supplier-search

---

## Как этим пользоваться

1. Пишете запрос обычными словами: «сыр моцарелла Казань», «мясо индейки», «мёд липовый в Питере». Город можно указать в запросе или выбрать в фильтре.
2. Получаете список производителей: сначала те, у кого это основной продукт, и те, кто ближе к вам. У каждого видно город, расстояние, контакты, сайт и ссылку на источник.
3. Открываете «Паспорт» поставщика. LLM разбирает полный текст карточки и собирает в одно место минимальный заказ, цену, фасовку, оплату, сертификаты (ГОСТ, ХАССП, «Меркурий», «Честный знак»), условия доставки, плюсы, риски и вопросы для первого звонка.
4. Добавляете 2–4 кандидатов в «Сравнение» (вручную или кнопкой «отобрать через AI»). LLM сравнивает их, советует, с кем связаться первым, кто будет запасным вариантом, и пишет черновик первого сообщения.
5. Ведёте статусы и заметки по поставщикам («Отправлен запрос КП», «Ждём прайс», …) с историей и авторами. Заметки разделены по организациям.

## Как это работает

```
запрос ─► разбор: продукт, уточнения, город
        ─► кандидаты: BM25 по полям + эмбеддинги (RRF), плюс поиск на productcenter.ru по фразе
        ─► переранжирование: cross-encoder bge-reranker-v2-m3 (локально, ONNX)
        ─► итоговый балл = 0.40·релевантность + 0.40·близость + 0.10·полнота карточки + 0.10·размер
        ─► карточки, паспорт по запросу (LLM, кэш в SQLite), сравнение и CRM
```

- **Релевантность.** Лемматизация `pymorphy3`, поиск по нескольким полям с разными весами (специализация, название, категория, описание). Отдельно различаются основной продукт и побочный («пельмени с курицей» не считаются поставщиком курицы), непищевые товары (корм, приправа, упаковка) и родительские категории (птицефабрика при запросе «индейка» получает частичный балл).
- **Гео.** Город берётся из запроса или фильтра, координаты — из офлайн-справочника на 1100 городов, а если города там нет — из Nominatim с кэшем. Близость считается так: `exp(-(d - d_min) / 400 км)`, то есть ближайший поставщик получает 1.0. Пока товар подходит плохо, близость влияет на балл слабо, чтобы соседняя, но нерелевантная компания не обгоняла нужную.
- **Данные.** Около 5000 производителей с productcenter.ru и agroserver.ru (`productcenter_parser.py`, `agroserver_parser.py`, `expand_catalog.py`). Для ~1300 из них LLM заранее разметил товары и признаки (`enrich_catalog.py`). Контакты и свежие компании подтягиваются с сайта прямо во время поиска (`live.py`). Если сайт начинает отвечать ошибками, на 5 минут включается пауза, и сервис работает только на своей базе.
- **Паспорт по запросу.** Заранее выкачивать и разбирать LLM всё подряд дорого, да и сайт за это блокирует. Поэтому подробное досье собирается только для поставщиков, которых открыли, и сохраняется в кэш.

## Почему такой формат

- **Streamlit + SQLite.** Работающий прототип в одном процессе, без отдельного фронтенда и сервера БД. Он разворачивается одной кнопкой, и его легко показать. Для боевой версии логика (`ranking.py`, `search.py`, `advisor.py`) не завязана на интерфейс и выносится в API как есть.
- **Локальные модели для поиска, LLM только там, где нужен текст.** Эмбеддинги и cross-encoder работают бесплатно и офлайн. LLM (Groq, OpenAI-совместимый API) вызывается только для паспорта, сравнения и черновика письма, и его ответы кэшируются. Без ключа API поиск, карточки и CRM работают, недоступны только AI-функции.

## Ограничения и что дальше

- Цена и минимальный заказ есть только там, где поставщик сам их указал. В остальных случаях это «по запросу», и сервис подсказывает, что спросить.
- База — снимок открытых каталогов. Дальше: регулярное обновление, больше источников (сайты производителей, Честный знак, ЕГРЮЛ для проверки юрлица), авторизация пользователей вместо выбора организации в списке.

## Качество поиска

`parser/eval_search.py` сравнивает варианты поиска на 21 запросе с ручной разметкой (`parser/eval_labels.json`):

| вариант | P@10 | nDCG@10 |
|---|---|---|
| только эмбеддинги | 0.33 | 0.57 |
| BM25 по полям | 0.61 | 0.88 |
| BM25 + эмбеддинги (RRF) | 0.53 | 0.75 |
| **+ cross-encoder (как в сервисе)** | **0.61** | **0.96** |

P@10 не может быть выше доли релевантных: по узким запросам («мясо индейки», «яйцо перепелиное») в базе всего 4–5 подходящих производителей. Поэтому главная метрика — nDCG. Слабее всего узкие запросы с составным названием: «колбаса копчёная» (P@10 0.1), «креветки замороженные», «тушенка» (0.2) — в карточках такие товары часто спрятаны в общем описании.

```bash
cd parser && python eval_search.py score   # пересчитать
cd parser && python eval_search.py pool    # кандидаты для доразметки
```

## Запуск локально

```bash
git clone https://github.com/andreimelneichuk/smart-supplier-search.git
cd smart-supplier-search
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # впишите ключ Groq или OpenAI, чтобы включить AI-функции
streamlit run parser/app.py
```

Готовая база (`parser/suppliers.db`) и кэш эмбеддингов лежат в репозитории, поэтому сервис работает сразу после клона. При первом поиске скачиваются модели эмбеддингов и cross-encoder (~0.6 ГБ).

## Деплой на Streamlit Community Cloud

1. share.streamlit.io → New app → этот репозиторий, ветка `main`, файл `parser/app.py`.
2. Advanced settings → Secrets:
   ```toml
   OPENAI_API_KEY = "gsk_..."
   OPENAI_BASE_URL = "https://api.groq.com/openai/v1"
   OPENAI_MODEL = "qwen/qwen3.8-27b"
   ```
   Streamlit сам передаёт эти значения в переменные окружения.

## Структура

```text
parser/
  app.py                 интерфейс (Streamlit)
  ranking.py             разбор запроса и итоговый балл
  search.py, bm25.py     лексический и векторный поиск, RRF
  cross_encoder.py       локальное переранжирование (ONNX)
  llm_rerank.py          опциональное переранжирование через LLM
  advisor.py             паспорт поставщика, сравнение, черновик письма
  geo.py, data/city.csv  координаты и расстояния
  live.py                подгрузка с productcenter.ru во время поиска
  db.py                  SQLite: поставщики, кэши, CRM
  *_parser.py, expand_catalog.py, enrich_catalog.py   сбор и обогащение базы
  eval_search.py, eval_labels.json                    оценка качества поиска
```
